# Document languages

`specarch document` writes every document target in English or in
Indonesian (ADR-241). English is the default; `--language id` writes
Indonesian, beside the English documents:

    specarch document techspec --language id --out docs/id spec
    specarch document html --language id --out site/id spec

A language other than English needs `--out`: the folder the
implementation files name holds the English documents, which `specarch
approve` compares, so a document in another language is written beside
them, never over them. It writes no region of `specarch.md`.

## What is translated

The headings, table headers, sentences and diagram labels the documents
write. The technical terms practitioners say in English stay as they
are: requirement, stakeholder, entity, field, endpoint, deploy, release,
rollback, test case, the priorities must, should and could, and the
like. The rest is the Indonesian a colleague would say in a meeting.

What stays as it is, in every language:

| Kept | Why |
|---|---|
| the specification's own words: titles, statements, descriptions, questions | they are the project's, written in the language it chose |
| the validator's, the approval's and the derived cases' messages | they are the validator's output, the same as `specarch validate` prints |
| the problem lines of `problems.txt` and `problems.sarif` | editors and the agent queue read their format; the headline of `problems.txt` is translated |
| the generated-file header (`Generated by specarch ...`) | tools recognise a generated file by it |
| element names, pointers, rule names, Mermaid keywords and HTML ids | links and tools read them |

## The catalogs

Each language other than English is a catalog embedded in the program,
`internal/generate/languages/<tag>/`, one YAML file per generator file:

```yaml
translations:
  "Version %s of the specification: %s.": "Spesifikasi versi %s: %s."
dynamic:
  "Roles and permissions": "Role dan permission"
same:
  - "erDiagram\n"
```

- `translations` gives each English text its translation. A text is a
  format with its fmt verbs; a translation formats the same values with
  the same verbs, and may reorder them with an explicit index, such as
  `%[2]s`, or leave a word out with `%.0s`, as Indonesian leaves out the
  copula.
- `dynamic` gives the texts the code makes as it runs, such as a section
  title made from its key, which no literal in the code names.
- `same` lists the English texts the language keeps as they are.

Two tests hold a catalog to the code. `TestCatalogsComplete` refuses a
text the documents write that the catalog does not give, and an entry no
document writes; `TestCatalogVerbs` refuses a translation whose verbs
differ from its English text. `TestDocumentsInEveryLanguage` writes every
target in every language and requires each document to differ from the
English one, every text to come from the catalog and every link to a
heading to reach one.

## Adding a language

1. Add the folder `internal/generate/languages/<tag>/`, and copy the
   files of `id/` into it as the list of texts to translate.
2. Translate each entry, keeping the verbs.
3. Add the tag to the `language` option's enum in
   `spec/design/commands/document.yaml`.
4. Run `go test ./internal/generate ./cmd/specarch`.

The vocabulary a document is read by is a separate file per language,
[`docs/vocabularies.md`](vocabularies.md).
