# 2026-10-25

## Paging names never empty in server/settings.ts (BUG-061)

Asked by the owner (item 1226), from a side finding of item 1209: the
Next.js generator wrote `server/settings.ts` with every paging wire name
empty when the ui target had `settings.server` and the specification no
`listOf`, and `tests/server.test.ts` paged by those empty names; visible
in the golden `generate-ui-typescript-estate-picker`, whose loans module
lists nothing itself. The names come from the paginated-list idiom, and
`specarch generate` hands a plug-in only the idioms whose keywords the
design uses (`reads: [listOf]`), so a design with no `listOf` gave the
plug-in no idiom and the generator wrote the names empty, saying nothing.

Decided after review: not a refusal. A module whose lists are all paged by
the server has no `listOf` by design (ADR-074), and refusing
`settings.server.pages` there would have left the feature usable only
beside some unrelated `listOf`. Instead the ui target's request carries
the paginated-list idiom whether or not the design has a `listOf`, for the
implementation files and the dependencies alike, with the file's exclusion
or override still applying (`validate.IdiomUsesWith`, `pluginIdioms`).
The generator, `forward.ts` and the derived test are unchanged;
`specarch idioms` and the documents list the idioms as before.

The other writers of these names were checked: the list page and the
picker of the Next.js, SwiftUI and plain JavaScript generators refuse
before writing when the names are missing, and SwiftUI writes no server
names; `server/settings.ts` was the one unguarded writer, and no example
output held an empty name (the estate's reading room is plain JavaScript).

The new golden `spec/tests/generate-ui-typescript-paged-whole` gives a
specification with no `listOf`, one list read whole and paged by the
server, and expects the names filled; its generated `tests/server.test.ts`
passes under node 26, and with the names emptied by hand its page test
fails, since the envelope's three members collide on one empty key. The
two estate-picker goldens changed in their `wire` line alone: the names
`page`, `pageSize`, `items`, `totalItems` and `totalPages` in place of
empty strings.

Files changed: `internal/validate/idioms.go`, `cmd/specarch/generate.go`,
`spec/design/commands/generate.yaml`,
`spec/requirements/requirements/design-keywords.yaml` (SA-56),
`docs/generators.md`, `docs/idioms.md`, the new case
`generate-ui-typescript-paged-whole`, the two estate-picker goldens,
`BUG_OUTSTANDING.md`, `BUG_HISTORY.md` and the regenerated documents.
Checked with `go test ./...`, `specarch validate spec examples` (the two
warnings pre-exist), `scripts/regenerate.sh` and `scripts/landing-check.sh`,
all passing. Release is left to the release chain, as for BUG-060; the tag
follows the review's approval. The handoff mailbox was empty. Nothing
was left out on purpose.
