# 2026-10-26

## Release 1.2.0

The owner asked for a release of the work on main since v1.1.0 (item
1254): the principle that a change carries its reason, the stated goal,
decision records naming the decisions they rest on under `restsOn`
(ADR-188, SA-97), checked in both validators and printed by `specarch
decision why` and `specarch decision rests`, and the review's fixes to
`decision_superseded`, the cycle error and the two-word commands under
`--json`, all on main at 0ea1d3c8.

The version is 1.2.0, not the 1.1.1 opened after v1.1.0: 1.1.1 was only
the next number, and the release proposes its own. Every change is an
addition: one optional key in the 1.0 design and implementation schemas,
two rules and two commands. A file with no error on 1.1.0 gets no new
error (`decision_superseded` is a warning, and the two errors need
`restsOn`, which no 1.1.0 file holds), and nothing a 1.1.0 run prints or
writes changes, so semantic versioning gives the minor step (rule 7,
`docs/maintenance.md`), as the meta-model 1.0.0 promise allows a 1.x
(ADR-186).

The release commit is made on main at 0ea1d3c8. The planned 1.1.1
release record becomes the 1.2.0 record, released (dated 2026-10-26, no
commit yet), and includes CR-3, a change record for the decision chain
(impact minor), so the release notes and the change register show it.
CR-3 names every element `specarch diff` finds changed since v1.1.0: it
adds SA-97, ADR-188, the two commands and their fourteen cases, and
changes the Rule enum; naming SA-97 alone left 18 elements uncovered.
`info.version`, both implementation files' `implements.version` and the
program version (`embed.go`, which every plug-in reports too, and the
Swift build's `programVersion`) are 1.2.0; the version case, the seven
model cases, `capabilities-text` and `guide-order-of-work` print 1.2.0,
and the six upgrade cases expect hints at v1.2.0, the tag upgrade
writes. The install lines in the README, `docs/from-sources.md` and the
plug-ins help topic point at v1.2.0. The roadmap gains its 1.2.0 row
and, with the README, calls 1.2.0 the latest. AGENTS.md and the
documents are regenerated.

The editor hints move where their schema changed. The 1.0 design schema,
its fragment schema and the 1.0 implementation schema gained `restsOn`
since v1.1.0, so a hint naming them at v1.0.0 would show `restsOn` as an
unknown key: the hints in `spec/`, the library lending and lending desk
examples, `docs/conventions.md`, the format help topic and the schema
line extract writes (`internal/extract/tree.go`) now name v1.2.0, and
the expected trees of the extract and merge cases with them. The hints
that name the 0.3 and 0.1 schemas and the idiom schema stay at v1.0.0,
since those files did not change; so do the hints in the input trees of
the cases, which stand for trees written earlier. `RUN_INSTRUCTION.md`
stays at v1.1.0, beside the module checksum it gives, until the tag
exists.

The owner added an SBOM to the release: `scripts/sbom.sh <version>`
writes `specarch-<version>.cdx.json`, the CycloneDX SBOM of the Go
module and the Swift package as the commit holds them, scans it with
grype and osv-scanner and the module's code with govulncheck, fails on
any finding, and lists each component's licence. It runs only the Go
module and Swift package catalogers, since syft's default set also read
an application bundle of the build Mac's system, and it writes the
files' paths as the repository names them, never the build machine's.
`CONTRIBUTING.md` gains a Releases section naming the steps, the SBOM
among them. The release ships no binary (it is installed with `go
install`), so there is no binary SBOM. Run on this commit's
dependencies: syft 1.55.0 found 16 components, grype 0.121.0 and
osv-scanner 2.7.0 found no vulnerability, govulncheck 1.8.0 none; the
licences are Apache-2.0, BSD-2-Clause, BSD-3-Clause and MIT, with the
Swift package's Yams MIT as `.dependency-allowlist.json` records. No
dependency changed since v1.1.0.

The schemas changed (`restsOn` in the design, fragment design and
implementation schemas of 1.0), which matters to a copy of the schemas
kept elsewhere; the copies are their owners' to move.

Open bugs, not in this release: none; `BUG_OUTSTANDING.md` lists none.

Checked: `scripts/landing-check.sh` passed in full; both builds print
1.2.0; `specarch diff` against v1.1.0 reports 19 elements changed, the
largest a minor addition, with no error. The handoff mailbox was empty.
Nothing was left out on purpose.

The tag v1.2.0, its GitHub release with the SBOM attached, the installs
and the release record's commit follow once this commit is approved and
on origin's main.
