## Every document as Markdown, Word or PDF

`specarch document <target> --format md|docx|pdf|all` writes a document
as Markdown (`<target>.md`, the default), Word (`<target>.docx`) or PDF
(`<target>.pdf`), several separated by commas, or all three, in the
target's folder (ADR-249, SA-149). A targets entry of an implementation
file may list `formats: [md, pdf]`, which a run without `--format` and
`specarch approve` follow; a format the target does not write is an error
at that entry, `document_format`, in both validator builds.

The owner asked for the documents in the form each reader uses: Markdown
for the repository, Word for review and sign-off, PDF for distribution.
The Word and PDF forms are rendered from the Markdown, each a book of the
document alone: front matter, a table of contents, the document, and the
Problems and gaps list linking every mark both ways. An invalid
specification still gets every format, and the run exits 1.

The pdf target of 2026-11-22 is now the `books` target, which writes its
four books as PDF (by default) or Word (`--format docx`), under names of
their own: `business-requirements`, `requirements-specification`,
`technical-specification` and `test-document`. The old names, brd.pdf
and requirements.pdf, are what `document brd --format pdf` and `document
requirements --format pdf` write now, in the same folder. No release
carried `document pdf`; `specarch document pdf` is a usage error that
names `books` and `--format pdf`.

The Word writer is SpecArch's own (`internal/docx`), on the standard
library (archive/zip and string building): content types, relationships,
document, styles, numbering, settings, font table, one header and one
footer, core and extended properties. Word's own heading 1 to heading 6
styles with outline levels, Word tables with a repeated header row, lists
through numbering (each numbered list from its own first number),
bookmarks for every heading, element id (`id_REQ_12`), mark and list
entry, hyperlinks for every link, a TOC field holding its entries, A4 with
the book and the version in the header and the page in the footer as
fields. Every part is written in a fixed order with each zip entry dated
1980-01-01 and no date, revision id or random id, so the same input gives
the same bytes and `--check` compares a docx byte for byte, as it does a
pdf. What a docx loses: the page numbers of the contents, which Word adds
when the reader updates the field, and embedded fonts (Calibri, and
Courier New for code, are named).

The work is in commit 4cd3ba663. Before the Word writer, the Markdown model moved from `internal/pdf` into
`internal/mdbook` (commit 9176fdab6), so the PDF and the Word writer read
the same blocks, anchors, id links and marks; the PDF books were byte for
byte the same after that move. The PDF's header now names the version, as
the Word document's does, and the Mermaid label says "this document"
rather than "the PDF", so the books' bytes changed with this item.

No dependency was added: the Word writer uses the standard library only.
`TestStructure` checks every package against the rules Word enforces when
it opens a file (content types, relationship targets, the schema's order
of children in pPr, rPr, tblPr, tcPr, sectPr and the styles, a paragraph
in every table cell, the grid matching the rows, sectPr last, every
style, numbering, bookmark and hyperlink resolved, no two tables
touching); `TestLibreOffice` converts a book to PDF where LibreOffice is
installed. Word itself was not available to open the files.

New cases: document-books (renamed from document-pdf-books),
document-books-gaps (from document-pdf-gaps), document-books-docx,
document-format-gaps (requirements in all three formats over an invalid
specification), document-format-from-targets, document-format-check-missing,
document-format-html-refused, document-format-books-md-refused and
validate-document-format. examples/library-lending writes its brd as md,
docx and pdf, the sample output of the Word and PDF forms.

The rename shows wherever a run lists the targets: the outputs table of
specarch gaps, the documents a change request reaches in the changes
register, and the usage line of specarch document in AGENTS.md and the
capabilities text, which now name books and --format. Those cases were
recorded again; the input changes.md of
approve-after-document-records-and-site names books in place of pdf.
Every example output of library-lending carries the digest of its
implementation file, which gained formats for the brd, so its generated
files were written again with the new digest and no other change.
