## Item 2169: diff reports a version that never stepped from a released one (BUG-075)

Summary: `specarch diff` between two folders at the same `info.version`
now reports `error: version:` and exits 1 when the release record beside
the old folder marks that exact version released. A version not yet
released, compared with itself as in a round of acceptance, still has
only its coverage checked (ADR-224).

- Why: the same-version skip held for any version, so a diff from the
  released 0.1.0 to a working tree still at 0.1.0 named no version
  problem, and a release whose `info.version` never stepped passed the
  version step of the release checklist under the number of the release
  before it.
- What decides "released": the release record of exactly the old
  version in the records beside the old folder, at `status: released`.
  A tag of the old version is the usual old folder, and its record
  already says released there (v1.5.0 and v1.6.0 do). The new folder's
  records do not decide: a round of acceptance that ends by marking the
  release released compares an approved commit still at `planned` with a
  working tree at `released`, and that is still one version not yet
  shipped.
- Not done on purpose: diff does not look up git tags, since it reads
  folders only, as its design says; a `withdrawn` release is not counted
  as spent, since the validator reads a withdrawn release as one that
  never ships (ADR-061). The suffix of the version (`-dev`, `-rc.1`) does
  not decide either: SpecArch's own working tree at a plain version with
  a planned release record is in a round too.
- The message names the record and the version to step to: the next
  version the change list needs from the old one, at least a patch step.
- Spec first: the design of `diff`, the consequences of ADR-224 and section 4 of `docs/acceptance.md` say
  the skip holds only for a version not yet released. The new test
  `diff-same-version-released` covers the released case;
  `diff-same-version` passes unchanged as the pre-release case.
- BUG-075 recorded in `BUG_OUTSTANDING.md` (its own commit), moved to
  `BUG_HISTORY.md` with this fix.

  Nothing was left out for being an employer's or client's.
