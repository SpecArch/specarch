# 2026-10-12

## The repository is secured on GitHub

The owner asked for the public repository to be locked down the way the
Go libraries already are. The settings were changed through the GitHub API
and each was read back:

- Rulesets with an empty bypass list: `protect-main` (the default branch
  cannot be force-pushed or deleted) and `protect-version-tags`
  (`refs/tags/v*` cannot be moved or deleted).
- Actions: only GitHub's own actions, verified creators and
  `pnpm/action-setup` may run, each pinned to a full commit SHA. The
  workflow token was already read-only, workflows already could not
  approve pull requests, and a first-time contributor's pull request
  already needed approval to run.
- Secret scanning and push protection on; Dependabot security updates on
  (alerts were already on); private vulnerability reporting on.
- Immutable releases on; the wiki and Projects off.
- CodeQL default setup on.

Files: `SECURITY.md` sends weaknesses to private vulnerability reporting.
`.github/dependabot.yml` watches the action SHAs and the Go modules
weekly; its comment says a Dependabot pull request skips the local
dependency scan, so each bump is taken in through a work item that runs
the SBOM scan, and the pull request is then closed. `ci.yml` says why its
trigger stays `pull_request` and never `pull_request_target`.

Decided: Issues stay on for bugs, questions and suggestions, with the rule
in `SECURITY.md` that a weakness is never described in an issue, pull
request or commit before the release tag that fixes it is out.

Left for the owner: the organisation settings (require two-factor
authentication, members may not create public repositories; the default
member permission is already read). The token in use lacks the
`admin:org` scope. Required commit signatures are not part of this step;
the signing key is still the owner's open decision.

Simulator: not needed, no app code.
