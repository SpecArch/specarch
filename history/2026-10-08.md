# 2026-10-08

The second release, v0.2.0, is tagged. It carries the open questions,
origin, `gaps`, `approve` and the generate gate, and the design of tests
derived from a specification. The editor hints and the README's install
line point at it.

## The second release tag

On the owner's word, v0.2.0 was tagged on the pushed head of main. The
open point at the end of the 2026-10-07 entry on open questions is closed
by it: v0.1.0 predates `questions`, `origin`, `decidedIn`, `answers`,
`reads`, `gaps` and `approve`, and the first jobs need them.

The head the owner named, 4cc0b6b, still printed version 0.1.0 in both
builds, so a binary installed from the tag would have reported the wrong
release. Commit 1c3d233 moved the program version to 0.2.0 in the Go and
Swift builds and in the case `version-prints-versions`, and the tag is on
that commit. The meta-model stays at 0.1, as does the specification's own
`info.version`, since neither the schema's name nor the version the
approval record and documents carry changed with the release. This choice
is the owner's to veto.

The tag is annotated, its message names partial specifications with open
questions, origin, `gaps`, `approve` and the generate gate, and it is
pushed. `go install github.com/SpecArch/specarch/cmd/specarch@v0.2.0`
resolves through the default module proxy and prints version 0.2.0.

The editor hint on the first line of every root and implementation file,
the two the conventions show, the one in the README and the README's
install line now name v0.2.0. The schema's `$id` stays on main, for the
reason given with v0.1.0. v0.1.0 is not moved.
