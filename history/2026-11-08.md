# 2026-11-08

## The README rewritten from the owner's draft

The README opens with the owner's draft, rephrased and checked against
the program and the repository: why SpecArch, what it does at each step
of the life cycle (extraction, validation and gaps, decisions and
approval, generation, tests, change and comparison), what shows a
specification, and a quick start. Everything the README said before
follows it as the reference part: the format, the rules, the repository
layout, installing and running, what the program says about itself, the
documents, from an old document to code, the status, the licence and the
SBOMs.

What in the draft did not match the program, and what the README says
instead:

- The draft named release v1.5.0 in a banner. The banner is left out,
  since it goes stale; the install lines carry the version (v1.7.0) and
  the status says 1.7.0 is the latest.
- The draft listed the technical specification, requirements, test plan,
  traceability matrix, commissioning checklist and release notes among the
  generators. They are `specarch document` targets; the generation section
  says so, and the documents section lists all twenty targets.
- The data-change scripts are for PostgreSQL and MariaDB only, and sqlc
  queries for PostgreSQL only; migrations and the seed cover all four
  databases.
- The draft's example of a conflict put the 14-day limit in SQL; in
  `examples/lending-desk/` it is in the Go service (`lending/model.go:8`).
- Interviews and decision tables are not extraction sources. What a
  stakeholder said is recorded with `specarch log`; a decision table is a
  form an algorithm takes. The gateway, systemd and tests readers, which
  the draft left out, are named.
- The draft named three UI generators; there are four (plain JavaScript as
  well). The seed, sqlc, register and BPMN generators are named too.
- Worked examples become tests through `specarch generate tests`, not
  `specarch derive`; derive writes the golden and red path drafts.
- The editor views the draft listed (readiness, traceability with test
  results, reach) are not in this repository. The README names what is:
  `document html`, the Mermaid diagrams, BPMN, `specarch model` for an
  editor and the schema hints, and says an editor can build such views on
  `specarch model`.
- The quick start's commands each lacked the folder, `decide` its question
  and answer, and `generate --unapproved` its target; the block was not
  closed. Each command names its folder; `decide` gives `--source`, which
  a specification that tracks origin asks for, and `approve` a session.
  They were run on copies of `examples/library-lending/` and
  `examples/lending-desk/` (with `--dry-run` where they write) and did
  what the README says; generation needs an implementation file and an
  approval, which the text after the block says. "Docker Compose" is
  Compose, and the commissioning checklist the commissioning procedure,
  as the program names them.

What the README said before that was stale: release 1.6.0 as the latest,
six examples (seven: `notice-board` is added to the layout), fifteen
idioms (seventeen) and fifteen documents (twenty). The list of verbs adds
`log`, `log test-run`, `run`, `compare`, `plan` and `upgrade`, the extract
sources gateway, systemd and tests, and the help topics start, asking and
situations. The editor hint stays at v1.6.0, as the 1.7.0 release left it.

Nothing of an employer or client was in the draft; nothing was left out
for that reason. The handoff mailbox was empty.

## The approve usage line names --session

The usage text `specarch` prints for a wrong command or `specarch help`
gave `approve --by <stakeholder> [--date <date>] [--dry-run] <folder>...`,
without `--session`, though `specarch help approve`, the README and
AGENTS.md give it. The line now reads `[--session <session>]` after
`--by`, in the order of the help topic.

Every other command's usage line was checked against every option its
help topic names, synopsis and option list both, and every option the
README writes after that command. One more was missing: the generate line
gave no `--environment`, though `specarch help generate` lists it among
its options and AGENTS.md gives it. The line, in the usage text and in
the package comment of `cmd/specarch/main.go`, now reads
`[--environment <environment>]` after `[--estate <file>]`, in the order of
the help topic's options. A first check had compared only the help
topics' synopsis lines, and generate's synopsis names no option; the
review found it. Every other option a help topic names and its usage line
does not is `--json`, which the usage text gives once for every command,
or an option of another command quoted in the topic (gaps quotes decide's
and approve's, mcp names capabilities' `--json` and the `--dry-run` of the
tools it serves).

Nothing of an employer or client was involved. The handoff mailbox was
empty.
