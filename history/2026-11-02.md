## Item 1690, round 2: routes answer 401, the nonce clause, the caching scope and the file a files route's test requests

Summary: the review of 4b7226fc asked for five changes, all taken: the
generated route guard answers 401 for a caller not signed in, the
derived golden of an application route names the nonce only when its
policy does, the technical specification names routes among what holds a
permission and writes each route's Cache-Control with its scope, and a
files route's test names the file it requests.

- `specarch-gen-go-dxlib`: the written handlers define `ErrNotSignedIn`;
  `routeGuard` answers 401 when `Allowed` returns or wraps it, or when the
  route's permission is `signedIn`, and 403 otherwise, so a service that
  mounts `RegisterRoutes` answers the statuses the validator gives the
  route and the cases `derive` writes. The compile-and-serve test covers
  the sentinel, a wrapped sentinel and a `signedIn` route.
- Both validators say "its policy naming a nonce made for this response"
  in an application route's golden only when a directive names `nonce`;
  `validate-routes-refused` re-recorded for route `asked`.
- The technical specification's Permissions paragraph names routes, and
  the Fixed routes table's Caching column reads as the server sends it,
  `public, max-age=...` or `private, max-age=...`, by the permission;
  every recorded technical specification re-recorded for the paragraph.
- A files route's test names its file as `input: { file: <path under the
  prefix> }`, checked in both builds (`file` alone, not empty, without a
  leading slash; `input` on another route is `test_data`), and the test
  generators request the prefix followed by the file; a files route test
  that names no file gets a body to write by hand, the comment saying
  why. The schema's `input` text, conventions, test-generation, ADR-216
  and SA-114 say so. New case `generate-tests-routes`;
  `validate-routes-valid` names the files in its tests;
  `validate-routes-refused` adds a file on a health route's test, a wrong
  key and a leading slash.
