# 2026-11-07

## Release 1.7.0

Summary: SpecArch 1.7.0 carries everything on main since v1.6.0: work
packages as records checked by seven rules and shown in the progress and
test plan documents (ADR-245, SA-140 to SA-142, CR-52), `specarch plan`
(ADR-246, SA-143 to SA-145, CR-53), and the fix of BUG-075, diff's
version check for a released version kept unchanged (CR-54). The owner
asked for the release, its tag, SBOM and install on 2026-11-06 and chose
1.7.0, the minor step, over the 2.0.0 that `specarch diff` asks for.

`specarch diff` from v1.6.0's `spec/` to this one: 37 elements changed
and one error, `version: 1.6.0 to 1.7.0 is a minor step, but
#/commands/diff needs a major step; release it as 2.0.0`. diff counts the
new path it reads (the release record beside the old folder) as a major
change to the diff command. The behaviour it changes is BUG-075's: a
same-version comparison of a released version exited 0 on 1.6.0 and
exits 1 now, which is what the design of diff always asked for; no
correct release relied on the old outcome. The owner's decision stands,
as for 1.6.0, and CR-54 says so in its decision with `impact: minor`.

The current build on v1.6.0's own `spec/` and `examples/` gives 0 errors
and the same 17 warnings as 1.6.0 does.

The planned 1.6.1 release record became 1.7.0
(`records/releases/1.6.1.yaml` renamed, released, dated 2026-11-07,
including CR-52, CR-53 and CR-54); nothing was planned under 1.6.1 but
the record. `info.version`, both implementation files'
`implements.version` and the program version (`embed.go`,
`programVersion` in the Swift build) are 1.7.0; the version case, the
seven model cases, capabilities-text, guide-order-of-work,
mcp-serves-tools and the guide by situation in both languages print
1.7.0. The install lines in the README, `RUN_INSTRUCTION.md`,
`docs/from-sources.md` and `docs/help/plugins.txt` move to v1.7.0. The
editor hints in the specification and in merge's and extract's output
stay at v1.6.0: since v1.6.0 only the record schema changed, and record
files carry no hint. The hints `specarch upgrade` writes name the
program's own version, so the six upgrade cases expect v1.7.0. The roadmap has the 1.7.0 row.
The documents and the skill are regenerated.

The decisions are dated 2026-11-06, the day the owner took them; the
release is dated 2026-11-07, the day it is tagged. The handoff mailbox
was empty. Nothing was left out on purpose.
