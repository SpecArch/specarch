# 2026-10-31

## Release 1.4.0: mapping examples and decide's restsOn (item 1575)

The owner asked for the work on main since v1.3.0 to be released and
installed. The request named a patch release for BUG-065, but main also
holds a feature: a call's mapping holding worked examples, checked by
validate, tried by operation and turned into tests (e4686bd5, ADR-207,
SA-106), with new optional keys in the 1.0 design schema. So the
release takes the minor step.

`specarch diff` from v1.3.0's `spec/` to this one: 17 elements changed
and one error, asking for 2.0.0, because `#/commands/try` loses its
argument `algorithm`: the first argument is now `name`, an algorithm's
name or an operationId. The owner decided on 2026-10-31 to read it as
not breaking and release 1.4.0: the argument is positional, so a
command line is written as before, and the one new refusal is a name
that is both an algorithm's and an operation's. CR-13's decision says
so. Every other element is covered by a change record the release
includes.

- CR-13 (impact minor): the mapping examples, ADR-207, SA-106, the try
  and validate cases, and the changed `#/enums/Rule` and
  `#/commands/try`.
- CR-14 (impact patch): decide writing `restsOn` for a question that
  blocks a decision, ADR-208, its three cases and the changed
  `#/commands/decide` (BUG-065, item 1574).
- The planned 1.3.1 release record becomes the 1.4.0 record, released,
  dated 2026-10-31, including CR-13 and CR-14.
- `info.version`, both implementation files' `implements.version`,
  `Version` in `embed.go` and `programVersion` in the Swift build are
  1.4.0; the version case, the seven model cases, capabilities-text and
  guide-order-of-work print 1.4.0.
- The 1.0 design schema changed since v1.3.0, so the hints naming it in
  `spec/`, the examples, the docs, the schema line extract writes and
  the extract and merge goldens move to v1.4.0. The implementation
  schema did not change, so its hints stay, except in the six upgrade
  cases, whose output names the running program's version.
- The install lines in the README, `docs/from-sources.md` and the
  plug-ins help topic move to v1.4.0; the README and the roadmap call
  1.4.0 the latest, and the roadmap gains its 1.4.0 row. AGENTS.md and
  the documents are regenerated.

Dependencies changed since v1.3.0: Go 1.27.3 in `go.mod` (666423d1), and
next 16.4.1 and zod 4.6.7 in the library lending web example's lock
(b804d7d9). `sh scripts/sbom.sh 1.4.0`: syft 1.55.0, 16 components;
grype 0.121.0, osv-scanner 2.7.0 and govulncheck found no
vulnerability; licences Apache-2.0, BSD-2-Clause, BSD-3-Clause and MIT
(Yams, the Swift build's one dependency, read from its licence file:
MIT).

Open bugs: none; `BUG_OUTSTANDING.md` lists none. The handoff mailbox
was empty. Nothing was left out on purpose. `RUN_INSTRUCTION.md` stays
at v1.3.0 until the tag exists.

The tag v1.4.0, its GitHub release with both SBOMs, the install on the
build Mac and opening 1.4.1 follow once this commit is approved and on
origin's main.

## Release 1.4.0: tag, GitHub release and install (item 1576)

main, so v1.4.0 is tagged on it (annotated, "SpecArch 1.4.0") and
pushed. The GitHub release v1.4.0 was made as a draft with notes

published it. The published notes hold no local path.

its twelve plug-ins on the build Mac; each binary's build information
names v1.4.0, `specarch version` prints 1.4.0, and the installed
`specarch validate spec examples` gives 0 errors and 3 warnings.
