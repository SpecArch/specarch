## extract go follows a helper that returns the group it makes

Reported from a project that extracts a Go codebase with 0.6.4: a gin
service registers routes on a plain group, through a local helper that
takes a prefix and a callback (read since 0.6.4, BUG-018), and through a
local helper that takes a prefix and returns the group, `g :=
returned("/d")` with routes on `g`. Expected 5 operations, got 3: the
two on the returned group were missing, with no question or warning.
BUG-022.

Cause, in `internal/extract/golang_routers.go`: a call of a function
value held in a local name, or bound to a parameter, was followed only
as a statement, never as a value. The router a call gives was a
library's maker, a group or subrouter, or what a function of the module
returns, so the name assigned from such a call held no router, and the
routes on it reached no registration, counted or asked. Latent beside
it: a literal's `return` set the return of the function it is written
in, so a function that declared such a helper and then returned its own
group could hand a caller the helper's group instead.

Fix: the walk of a literal gives the router the literal returns and
keeps the return of the function it is written in apart from it; a call
of a held function gives that router, so a call of one is the call's
value, and the statement walk leaves a call already followed as a value
alone. The walk paragraph of `spec/design/commands/extract.yaml` says
that the router such a call returns is the call's value, a literal's
return never standing for the return of the function it is written in;
`docs/extraction.md` step 15 says a helper returning the group it makes
is followed through its value; `docs/techspec.md` is regenerated, the
other document targets unchanged.

Tests: `TestGoRouterReturnedByHelper` in
`internal/extract/golang_test.go`, seven cases: a closure returning the
group assigned in a block, one called with two prefixes and in a chain,
one registering a route before it returns, one passed to a function of
the module that calls it for the group, a function of the module
returning the group called by name and passed as a value, and a literal
whose return must not become the return of the function around it
(which wrote a route under the wrong group before). All seven failed
before the fix and pass after it, together with
`TestGoLiteralSeesWhereItIsWritten`, which now shares the harness
`goRoutesCases`. The whole module passes `go test ./...`, the validator
passes on `spec/` and `examples/`, and every document target checks
clean.

Left out on purpose: the reporter's service names, route names and
route counts. Not touched: the Swift build (extract is Go only), and
ADR-081 and `docs/reading-code.md`, which do not state the walk at this
level. The handoff mailbox folder was empty. The fix is commit dda47fdd;
the commit after it records that hash here and in `BUG_HISTORY.md`.

## merge adds up a role's grants from trees that declare different permissions (ADR-127)

Handoff 15 processed. A specification merged from the permission tables
of several services, one tree each, lost every grant of a role that was
in more than one table: merge compared the two lists as any key, left
the role's `permissions` out with a must question asking which list is
right, and the question blocked every permission the lists name that no
other role grants. The sender expected the union of the lists with both
citations and no question.

Rule chosen: a tree's list of a role's grants says nothing of a
permission the tree does not declare in its `permissions` section, so
the lists of several trees add up, the first tree's then what each
later tree adds, with every tree's citation and one "joined:" line
naming the trees. A permission one tree grants that another tree, which
has the role, declares and does not grant is still a disagreement: the
list is left out, and the must question names each such permission
with the trees that grant and withhold it, beside the lists each tree
gives, and blocks the ungranted permissions as before. A role a printed
and a parsed tree both give is still compared grant by grant with the
printed grants kept. Not taken: the handoff's rule of joining the lists
whenever the trees come from different sources, since a documents tree
that lists a role's permissions and leaves one out would then be joined
silently with the code that grants it, against "never choose between a
document and the code"; and two trees of one source key are already
joined or refused as one source, so the only same-source case left is
printed against parsed. The handoff's own term for the merged files was
left out of the repository.

Code: `roleGrants` in `internal/extract/merge.go`, run after the last
tree is in and before the disputed keys are left out, so the order the
trees are given no longer decides whether a list is a dispute (the old
check in `mergeNode` saw only the trees read so far); `mergeNode` skips
a role's `permissions`; `disputeQuestions` words the why of such a
dispute with the grant withheld. Design: the rule in
`spec/design/commands/merge.yaml` and its standard output line, the
new ADR-127 with its reason, a bullet in SA-45's acceptance list, and
the paragraph in `docs/from-sources.md`, section 3.2. `docs/extraction.md`
is unchanged: the lending desk's roles are printed and parsed, which
this does not touch.

Cases: new `merge-role-grants-add-up` (two services' tables, each
declaring its own permissions and granting one role of the same name
its own: the role gets both grants with both citations, the joined line,
and no question on the grants) and `merge-role-grants-withheld` (both
tables declare one permission, one grants it to the role and the other
has the role and withholds it: the list is left out and the must
question says which tree grants and which withholds). `merge-role-names-
disagree` already held this very dispute beside the wire-name question
it is about; its role now gets every grant of both tables and only the
wire-name question is asked.

Checks: `go test ./...` with the conformance suite, `swift test`,
validate on `spec` and `examples` (0 errors; SA-57 unverified as
before), the Go and Swift validators print the same output on `spec`,
`examples` and both new merged trees, and `examples/lending-desk/extract.sh`
run with the binary before and after writes the same bytes. Every
document target of CI regenerated. No dependency change. The ISI
mailbox folder is empty; the handoff was a queue handoff, with nothing
to delete there. Simulator: not needed, no app code.
