# 2026-10-29

## scripts/sbom.sh writes its results to sbom/local/ (item 1571)

Owner's request: check that the SBOM scan script works and have it leave
its output in `sbom/` of the folder it is run from.

Run as it was (`sh scripts/sbom.sh 1.3.1`), the script passed: syft
1.55.0 wrote the SBOM, and grype 0.121.0, osv-scanner 2.7.0 and
govulncheck found nothing. Nothing had to be fixed. It wrote the SBOM
into the folder it was run from and left the scanners' reports only on
the terminal.

Now it writes everything to `sbom/local/<version>/` (created if missing;
`<out-dir>` still overrides it): the CycloneDX SBOM, `grype.txt`,
`osv-scanner.txt`, `govulncheck.txt` and `licences.txt`. The reports have
the repository's own path taken out, since osv-scanner printed the
SBOM's absolute path. A scanner's exit status still fails the script,
which now names the report file.

The release records in `sbom/<tag>/` are written by the release step,
not by this script, and it refuses an `<out-dir>` inside one of them.
`sbom/local/` is gitignored: a scan before tagging is a check on the
working copy, not a record, and committing it would put unreviewed
results beside the release records and dirty the tree on every run.
The header comment and CONTRIBUTING.md's Releases section say so.
